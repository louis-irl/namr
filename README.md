**Namr** (`fans.bingus.namr`) is a fast, native desktop application for bulk renaming files and directories. Built with **Python**, **PySide6 (Qt6)**, and **KDE Kirigami**, it pairs a clean split-pane interface with live inline diff previews, hierarchical tree browsing, real-time conflict detection, and full multi-step undo support.

## Features

- **Live Find & Replace with Inline Diffs**
  - Instant preview as you type—matched text is highlighted in red strikethrough in the **Original Name** column and in green in the **New Name (Preview)** column.
  - Toggle **Case sensitive** matching and **Include file extension** (preserves extensions by default, including dotfiles like `.bashrc`).
  - Filter the scope to **Files and Folders**, **Files Only**, or **Folders Only**.
  - Filter the preview table with **Show only affected items** to focus exclusively on items modified by the current rule.
- **Hierarchical Tree View & Flexible Loading**
  - **Drag and drop** files and folders directly from Dolphin or any file manager.
  - Native XDG Desktop Portal file (`Ctrl+O`) and folder (`Ctrl+Shift+O`) pickers.
  - **Recursive subfolder scanning** enabled by default, presented in a collapsible directory tree with cascading folder checkboxes.
  - Launch directly from the terminal or via your file manager's **Open With** menu.
- **Safety, Validation & Full Undo**
  - **Real-time conflict detection**: Prevents batch execution whenever duplicate target names or existing on-disk file collisions are detected.
  - **Cross-platform filename validation**: Optional strict Windows/macOS compatibility check (enabled by default) warns on reserved characters (`< > : " / \ | ? *`), control characters, trailing dots/spaces, and reserved device names (`CON`, `NUL`, `COM1`, etc.).
  - **Two-phase depth-sorted execution**: Safely renames deepest nested children before parent directories and uses temporary staging paths to resolve overlapping swap chains (`a → b`, `b → c`) in the same directory without data loss.
  - **Undo stack (`Ctrl+Z`)**: Revert completed rename batches in reverse order.

## Installation

### Option 1: Flatpak (Recommended)

Ensure `flatpak` and `flatpak-builder` are installed along with the KDE Plasma 6.11 runtime and PySide6 BaseApp from Flathub:

```bash
flatpak install flathub org.kde.Platform//6.11 org.kde.Sdk//6.11 io.qt.PySide.BaseApp//6.11
```

Build and install for the current user:

```bash
flatpak-builder --user --install --force-clean build-dir flatpak/fans.bingus.namr.json
```

Run the installed Flatpak:

```bash
flatpak run fans.bingus.namr
```

#### Exporting a standalone `.flatpak` bundle

To package the application into a single `.flatpak` file that can be installed later or copied to another machine:

```bash
flatpak-builder --force-clean --repo=repo build-dir flatpak/fans.bingus.namr.json
flatpak build-bundle repo namr.flatpak fans.bingus.namr
```

Install the bundle with:

```bash
flatpak install --user namr.flatpak
```

### Option 2: Run from Source (Arch Linux / KDE Plasma 6)

1. Install the required system packages:

   ```bash
   sudo pacman -S python pyside6 kirigami kirigami-addons qqc2-desktop-style
   ```

2. Clone the repository and install in editable mode (or run directly):

   ```bash
   git clone https://github.com/louis-irl/namr.git
   cd namr
   pip install --no-build-isolation --no-deps -e .
   namr
   ```

   Or run directly without installing:

   ```bash
   PYTHONPATH=src python3 -m namr.main
   ```

## Usage

### Command Line

Pass any combination of files and directories on startup:

```bash
namr ~/Pictures/Vacation ~/Documents/report_draft.pdf
```

### Keyboard Shortcuts & Interactions

| Shortcut / Action | Description |
| :--- | :--- |
| `Ctrl+O` | Open the **Add Files…** dialog |
| `Ctrl+Shift+O` | Open the **Add Folder…** dialog |
| `Ctrl+Z` | **Undo** the most recent rename batch |
| `Tab` / `Shift+Tab` | Navigate sequentially through sidebar controls |
| `Double-Click` (on folder row) | Expand or collapse folder contents in the preview tree |

## Architecture

The codebase is organized with a strict separation between filesystem/rule logic and the Qt6/QML user interface:

```text
namr/
├── data/
│   ├── fans.bingus.namr.desktop       # Freedesktop launcher & Open With integration
│   ├── fans.bingus.namr.metainfo.xml  # AppStream metadata
│   └── fans.bingus.namr.svg           # Scalable application icon
├── flatpak/
│   └── fans.bingus.namr.json          # Flatpak builder manifest
├── src/namr/
│   ├── core.py        # Pure-Python rule protocol, diff generator, validator, and batch/undo engine
│   ├── controller.py  # QAbstractListModel tree projection and QML controller properties/slots
│   ├── main.py        # CLI argument parser, portal/style setup, and QQmlApplicationEngine entry point
│   └── qml/
│       └── Main.qml   # Kirigami split-view UI, resizable preview table, and toast notifications
└── tests/
    └── test_core.py   # Unit and controller test suite
```

The rule engine in [`src/namr/core.py`](src/namr/core.py) defines a pluggable `RenameRule` protocol, making it straightforward to add new rule types (such as Regular Expressions, Sequential Numbering, Case Conversion, or Media/EXIF Metadata) alongside `FindReplaceRule`.
